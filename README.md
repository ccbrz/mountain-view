# Mountain View

AI 小说创作平台，支持多用户、角色权限管理、LLM 配置接入，自动生成小说章节。

## 技术栈

- **前端**: React 18 + TypeScript + Vite + Ant Design
- **后端**: Express + TypeScript + better-sqlite3
- **认证**: JWT + bcryptjs

## 目录结构

```
├── client/          # 前端 (React + Vite)
├── server/          # 后端 (Express)
├── data/            # SQLite 数据库文件 (gitignore)
├── railway.json     # Railway 部署配置
└── package.json     # 根 scripts
```

## 快速开始

### 1. 安装依赖

```bash
# 根目录
npm install

# 前端
cd client && npm install

# 后端
cd ../server && npm install
```

### 2. 初始化数据库

```bash
npm run db:seed
```

创建默认账号：`admin` / `950711`

### 3. 启动开发环境

```bash
npm run dev
```

- 前端: http://localhost:5173
- 后端: http://localhost:3001
- 前端通过 Vite proxy 将 `/api/*` 转发到后端

### 4. 构建生产版本

```bash
npm run build    # 构建前端到 client/dist/
npm start        # 启动后端，自动托管前端静态文件
```

## 小说上下文维护

右下角「LLM 调试」悬浮按钮支持「对话测试」和「调用日志」。对话测试可选择当前项目任务已配置的对话模型（不包含单独配置的 Embedding），支持多轮消息和可选系统提示。切换模型会新建会话；消息仅在当前页面保留，不注入小说上下文、不写正文或记忆。每次发送只调用一次，失败保留输入；上游提供的内容过滤、拒绝和截断标记会显示出来。离线验证：`pnpm --filter server test:chat`。

台本整理使用「AI 整理台本」入口：原稿与候选并排核对，候选可直接编辑和保存，关闭窗口时会保存未提交的候选修改。默认保留全部对白；只有勾选「允许压缩非关键对白」才请求压缩。AI 推断的限制单独显示为补充建议，默认不加入候选；前文矛盾仅作提醒。点击「采纳为当前台本」后才替换台本，并自动归档原稿，可从「台本版本」恢复。候选、历史版本存入数据库，刷新后仍可继续。采纳和恢复不改正文或已确认的记忆；台本/上下文变更后，旧候选不能直接采纳，需重新整理。

台本回归：`pnpm --filter server test:outline-review`，离线验证候选保存、人工采纳、版本恢复、并发冲突、异常输出、权限和归档失败回滚。

正文或剧情设定变更后，受影响的进度快照和检索索引会失效，后续章节保留正文并标记为待审校。请从提示的章节开始按顺序定稿；删除中间章节后，点击新建会优先补齐章号缺口。索引失败可点击「重试索引」，无需重新生成进度。

首次升级到带上下文版本检查的版本时，旧快照无法验证与正文的一致性，会清空旧进度和索引，保留所有正文及修订历史。章节页会提示从最早未定稿章节开始，逐章「核对记忆并定稿」，无需重写正文。后续启动不会重复清理。

人工定稿流程：打开章节 →「核对记忆并定稿」→ 手工填写或点击「AI 整理记忆与审校」→ 核对摘要、当前事实、未解伏笔和下一章衔接 → 勾选确认 →「确认记忆并定稿」。事实可修改或删除，已揭晓的伏笔可关闭；核对草稿可保存后继续。AI 意见仅供参考，误报、模型故障或未配置模型都不会阻止作者手工确认。确认不调用模型或向量服务，直接保存作者确认的记忆；向量索引可之后单独重试，期间可用历史原文检索。

已定稿章节可通过「核对 / 修正记忆」修改；确认旧章修改会使后续章节待重新核对，正文保留。正文或设定在核对期间发生变化、另一窗口已保存核对草稿时，旧核对结果会被拒绝，需重新载入。系统保留本次候选记忆、参考意见、作者确认结果与确认人、时间。

长篇存储中，章节摘要每章只保存一份，进度快照仅保存当时的事实、伏笔和衔接状态。已有版本保护的快照会在启动时自动拆分摘要，保留定稿状态；迁移遇到缺失或损坏的摘要会整体回滚。章节目录和进度目录不携带正文，打开对应章节或历史进度时才加载内容；全文只在导出时读取。起草、审稿仍使用最近三章摘要和目标章节之前的状态。

离线回归：`pnpm --filter server test:context`（使用内存数据库和模拟模型，不读取业务数据或调用外部服务）。

长篇规模回归：`pnpm --filter server test:context-scale`，使用 500 章、每章 2,000 字正文和 250 字摘要的合成数据，验证迁移、回滚、历史边界和存储/响应体缩减，并打印前置检查耗时。数据量指标是有效载荷大小，不是 SQLite 文件大小；该检查不衡量生成质量。

20 章真模型实验：`pnpm --filter server test:memory-20`。只读第一部小说的模型配置，在内存数据库中逐章起草、定稿，目标每章 2,000 字；正文、记忆快照、提示词和第 5/10/15/20 章的记忆问答保存至独立 `demo-output/memory-20-*` 目录。会调用真实模型并产生费用，不修改业务小说。可追加已有输出目录从完整章节检查点继续。Embedding 首次请求限时 30 秒，失败后本轮不再重试；该情况下报告索引未完成，不能据此评估检索质量。执行完成不等于质量通过，应按 `memory-20-fixture.ts` 的独立答案核对证据。

Embedding 需选支持 `/embeddings` 的模型，选择时会进行真实向量预检，设置中的「测试向量」与「测试对话」分开。向量请求最多等待 30 秒（含完整响应体），并校验非空、有限、非零向量；更换向量模型会使索引待重建。无向量或服务失败时，使用 SQLite 中文全文索引检索本书已定稿的历史原文，仍严格限制章节边界。检索片段保留来源，不再通过重排模型改写。

起草会核验有证据的连续性矛盾，初审问题经过复核；可自动修复一次，仍有疑点时保存待审草稿并显示提示，旧稿保留在修订记录中。草稿不进入记忆或检索。页面定稿以作者核对结果为准，仍检查必填项、事实结构、前章完整性和上下文版本。供实验脚本兼容的自动定稿接口继续保留严格的模型核验；模型仍可能漏报或误报。

人工流程回归：`pnpm --filter server test:human-review`，使用隔离数据库与模拟模型，验证人工修改事实、关闭伏笔、误报处理、无模型定稿、核对草稿、并发保护、事务回滚和旧章节顺序恢复，不调用外部服务。

修复回归：`pnpm --filter server test:memory-repair`，离线验证超时、向量格式、事实/伏笔校验和原文检索。追加 `--live` 使用现有 `demo-output/memory-20-2026-10-06T01-53-54-734Z` 中的 20 章证据复测已知失败案例，调用真实模型、业务库只读。

真实复测可再追加 `--detect-only=19`（或 `6`）、`--state-only=16`（或 `4`）、`--api-only` 或 `--controls-only` 单独重跑相应阶段，避免重复消费已通过的案例。检测、状态或反例对照可加 `--model=模型名` 临时比较模型，不改业务配置。断言失败会非零退出，不能把调用完成或某次重试通过当成稳定准确率。

## 环境变量

在根目录创建 `.env` 文件：

| 变量 | 说明 | 默认值 | 必需 |
|------|------|--------|------|
| `PORT` | 后端端口 | `3001` | 否 |
| `NODE_ENV` | 运行环境 (`production` / `development`) | 无 | 否 |
| `JWT_SECRET` | JWT 签名密钥 | **必填，无默认值** | **是** |
| `DB_PATH` | SQLite 数据库路径 | `data/app.db` | 否 |
| `ALLOWED_ORIGINS` | 允许的 CORS 域名，多个用逗号分隔 | 生产环境无默认值 | 否 |

> `JWT_SECRET` **必须设置**，缺失时服务启动会报错退出。

## 部署

项目已配置 Railway 部署（`railway.json`），推送代码后在 Railway 关联仓库即可自动部署。

### Railway 部署注意事项

- **必须设置环境变量** `JWT_SECRET`
- 建议设置 `NODE_ENV=production`
- **必须挂载持久化 Volume** 到 `data/` 目录（SQLite 数据库），否则每次重启数据会丢失
- 可选：`ALLOWED_ORIGINS` 如不设置，生产环境默认拒绝所有跨域请求

### 首次部署后

1. 在 Railway Dashboard 打开项目 Shell，运行 `npm run db:seed` 初始化数据库
2. 默认账户：`admin` / `950711`
3. 建议首次登录后立即修改默认密码
