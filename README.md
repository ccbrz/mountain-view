# Mountain View

AI 小说创作平台，支持多用户、角色权限管理、LLM 配置接入，自动生成小说章节。

## 技术栈

- **前端**: React 18 + TypeScript + Vite + Ant Design
- **后端**: Express + TypeScript + better-sqlite3
- **认证**: JWT + bcryptjs

## 目录结构

```
├── client/          # 前端 (React + Vite)
├── server/          # 后端 (Express)
├── data/            # SQLite 数据库文件 (gitignore)
├── railway.json     # Railway 部署配置
└── package.json     # 根 scripts
```

## 快速开始

### 1. 安装依赖

```bash
# 根目录
npm install

# 前端
cd client && npm install

# 后端
cd ../server && npm install
```

### 2. 初始化数据库

```bash
npm run db:seed
```

创建默认账号：`admin` / `950711`

### 3. 启动开发环境

```bash
npm run dev
```

- 前端: http://localhost:5173
- 后端: http://localhost:3001
- 前端通过 Vite proxy 将 `/api/*` 转发到后端

### 4. 构建生产版本

```bash
npm run build    # 构建前端到 client/dist/
npm start        # 启动后端，自动托管前端静态文件
```

## 写作台

从「幻想小说家」打开具体小说后，直接进入占满窗口的写作台。左侧只保留书名、章节目录、新建章节和全书导出；点击书名打开作品设置，每章「⋯」菜单提供重命名、删除和台本版本（启用检索时也可更新索引）；全文精修与确认定稿放在当前正文末尾。右侧直接维护 Memory／Lorebook，Memory 旁「历史」支持查看并显式恢复有效快照；文风与范文、模型管理在「参数」中打开。移动端通过顶部按钮展开章节与写作设置。返回书架会提示先保存未保存编辑。

- 顶部主题选择可在「经典深色」「龙与地下城」间切换。背景和配色仅影响界面，偏好按账号保存在当前浏览器，不进入提示词，也不修改作品设定。原创主题插画由内置 imagegen 生成，资产位于 `client/public/themes/dragon-dungeon.png`。
- 整章台本直接生成或续写，不需要拆场景；选中正文后可填写修改要求，先比较候选，再接受替换选区。
- 作者批注按章保存；Memory 与 Lorebook 按小说保存。世界与人物直接管理同一份 Lorebook，支持分类、搜索和 JSON 导入导出。首次打开自动合并旧架构与角色；与已编辑条目存在差异的旧资料作为停用条目保留，供作者核对。原始资料保留在数据库和 JSON 备份中。关键词出现在台本、当前正文或近期前文时激活，支持常驻。
- 复用原有 LLM 配置、文风指南、范文片段和去 AI 味提示词。写作台只发送当前台本、正文、近期前章结尾、Memory 和激活设定，不默认叠加旧多层摘要或依赖 Embedding。Memory 是当前有效记忆的唯一来源，生成、审稿与台本整理共用；不再从旧进度复制或维护第二份事实表。全书 Memory 由作者确认维护；回头重写时可显式预览并恢复有效的章前版本，当前记忆会先备份。
- 「本次上下文」展示将发出的完整请求；「上次实际请求」和生成历史展示当时的请求与所用模型。NovelAI 的容量提示使用官方 tokenizer 计数（消息格式另留余量）；其他服务或计数接口不可用时使用 UTF-8 保守估算。
- 每次成功生成、改写和 Memory 建议自动存入 SQLite 的 `writer_artifacts`。正文生成及手工编辑通过自动保存更新 `novel_chapters`；旧正文和台本分别进入原有修订记录，沿用后续记忆失效保护。未保存编辑备份在当前浏览器，按账号与小说隔离。
- 「AI 整理台本」复用原有工具；正文统一使用「全文精修」入口。「确认本章定稿」先根据已保存正文自动整理 Memory 建议，核对后原子保存正文定稿状态、当前 Memory 和历史快照，不再维护另一套结构化记忆。Memory 修改和章节定稿都会写入`writer_memory_history`；Memory 旁「历史」支持预览并显式恢复可用版本；历史不会自动混入请求。旧进度快照会一次性归档；已有 Memory 优先保留。保存与定稿均检查原始版本，失败回滚。
- 可下载按章排序的 TXT、Markdown；JSON 归档包含正文、设定、生成记录、修订及记忆核对数据，不含模型密钥。当前 JSON 是文件备份，没有一键导入恢复界面；部署仍需持久化备份 SQLite。

离线回归：`pnpm --filter server test:writer`，使用隔离数据库和模拟模型验证权限、上下文、历史归档、选段修改、并发保存和导出，不读取业务模型或调用真实服务。

## 小说上下文维护

固定写作要求的默认模板强调创作简体中文小说：普通叙述、对白、技术词汇与设施名称使用通行中文，避免无必要的中英混写；作者指定的外文专名、型号、代码和必要缩写保留。规则可编辑或删除，生成时只使用当前保存的文本。旧版未修改的默认模板升级到版本 3，自定义要求和已清空的规则保持不变。

写作台顶部「保存修改」只保存本书设置（Memory、Lorebook、写作参数等）。正文生成完成后立即保存；手动修改正文、章节标题、台本或作者批注后，停止编辑 3 秒自动保存本章。底部显示等待、保存中、已保存或失败状态；失败保留当前编辑并支持重试，不自动覆盖其他窗口的改动。切换章节、返回书架和导出前会先完成本章保存。自动保存不等于定稿，定稿仍需作者确认。

右侧「AI 看到了什么 → 高级 · 模型调试」支持「对话测试」和「调用日志」。对话测试可选择当前项目任务已配置的对话模型（不包含单独配置的 Embedding），支持多轮消息和可选系统提示。切换模型会新建会话；消息仅在当前页面保留，不注入小说上下文、不写正文或记忆。每次发送只调用一次，失败保留输入；上游提供的内容过滤、拒绝和截断标记会显示出来。离线验证：`pnpm --filter server test:chat`。

台本整理使用「AI 整理台本」入口：原稿与候选并排核对，候选可直接编辑和保存，关闭窗口时会保存未提交的候选修改。默认保留全部对白；只有勾选「允许压缩非关键对白」才请求压缩。AI 推断的限制单独显示为补充建议，默认不加入候选；前文矛盾仅作提醒。点击「采纳为当前台本」后才替换台本，并自动归档原稿，可从「台本版本」恢复。候选、历史版本存入数据库，刷新后仍可继续。采纳和恢复不改正文或已确认的记忆；台本/上下文变更后，旧候选不能直接采纳，需重新整理。

台本回归：`pnpm --filter server test:outline-review`，离线验证候选保存、人工采纳、版本恢复、并发冲突、异常输出、权限和归档失败回滚。

当前写作台只维护 Memory 与 Lorebook。定稿快照不会随正文或设定变更而删除，也不会被自动回填到当前记忆；JSON 备份包含完整记忆历史。旧章正文修改后，后续章节仍保留并标记待核对。审稿、台本整理和兼容正文修订读取统一设定与当前 Memory，不再强制补齐旧进度链；近期前文直接读取已保存正文，不走旧摘要和向量检索。

以下结构化进度流程仅供尚未打开新版写作台的旧项目和历史实验脚本使用。小说初始化为新版后，旧记忆编辑、自动定稿、世界观生成和旧设定保存接口会拒绝写入，避免产生第二个来源。

正文或剧情设定变更后，受影响的进度快照和检索索引会失效，后续章节保留正文并标记为待审校。请从提示的章节开始按顺序定稿；删除中间章节后，点击新建会优先补齐章号缺口。索引失败可点击「重试索引」，无需重新生成进度。

首次升级到带上下文版本检查的版本时，旧快照无法验证与正文的一致性，会清空旧进度和索引，保留所有正文及修订历史。章节页会提示从最早未定稿章节开始，逐章「核对记忆并定稿」，无需重写正文。后续启动不会重复清理。

人工定稿流程：打开章节 →「核对记忆并定稿」→ 手工填写或点击「AI 整理记忆与审校」→ 核对摘要、当前事实、未解伏笔和下一章衔接 → 勾选确认 →「确认记忆并定稿」。事实可修改或删除，已揭晓的伏笔可关闭；核对草稿可保存后继续。AI 意见仅供参考，误报、模型故障或未配置模型都不会阻止作者手工确认。确认不调用模型或向量服务，直接保存作者确认的记忆；向量索引可之后单独重试，期间可用历史原文检索。

已定稿章节可通过「核对 / 修正记忆」修改；确认旧章修改会使后续章节待重新核对，正文保留。正文或设定在核对期间发生变化、另一窗口已保存核对草稿时，旧核对结果会被拒绝，需重新载入。系统保留本次候选记忆、参考意见、作者确认结果与确认人、时间。

长篇存储中，章节摘要每章只保存一份，进度快照仅保存当时的事实、伏笔和衔接状态。已有版本保护的快照会在启动时自动拆分摘要，保留定稿状态；迁移遇到缺失或损坏的摘要会整体回滚。章节目录和进度目录不携带正文，打开对应章节或历史进度时才加载内容；全文只在导出时读取。起草、审稿仍使用最近三章摘要和目标章节之前的状态。

离线回归：`pnpm --filter server test:context`（使用内存数据库和模拟模型，不读取业务数据或调用外部服务）。

长篇规模回归：`pnpm --filter server test:context-scale`，使用 500 章、每章 2,000 字正文和 250 字摘要的合成数据，验证迁移、回滚、历史边界和存储/响应体缩减，并打印前置检查耗时。数据量指标是有效载荷大小，不是 SQLite 文件大小；该检查不衡量生成质量。

20 章真模型实验：`pnpm --filter server test:memory-20`。只读第一部小说的模型配置，在内存数据库中逐章起草、定稿，目标每章 2,000 字；正文、记忆快照、提示词和第 5/10/15/20 章的记忆问答保存至独立 `demo-output/memory-20-*` 目录。会调用真实模型并产生费用，不修改业务小说。可追加已有输出目录从完整章节检查点继续。Embedding 首次请求限时 30 秒，失败后本轮不再重试；该情况下报告索引未完成，不能据此评估检索质量。执行完成不等于质量通过，应按 `memory-20-fixture.ts` 的独立答案核对证据。

Embedding 需选支持 `/embeddings` 的模型，选择时会进行真实向量预检，设置中的「测试向量」与「测试对话」分开。向量请求最多等待 30 秒（含完整响应体），并校验非空、有限、非零向量；更换向量模型会使索引待重建。无向量或服务失败时，使用 SQLite 中文全文索引检索本书已定稿的历史原文，仍严格限制章节边界。检索片段保留来源，不再通过重排模型改写。

起草会核验有证据的连续性矛盾，初审问题经过复核；可自动修复一次，仍有疑点时保存待审草稿并显示提示，旧稿保留在修订记录中。草稿不进入记忆或检索。页面定稿以作者核对结果为准，仍检查必填项、事实结构、前章完整性和上下文版本。供实验脚本兼容的自动定稿接口继续保留严格的模型核验；模型仍可能漏报或误报。

人工流程回归：`pnpm --filter server test:human-review`，使用隔离数据库与模拟模型，验证人工修改事实、关闭伏笔、误报处理、无模型定稿、核对草稿、并发保护、事务回滚和旧章节顺序恢复，不调用外部服务。

修复回归：`pnpm --filter server test:memory-repair`，离线验证超时、向量格式、事实/伏笔校验和原文检索。追加 `--live` 使用现有 `demo-output/memory-20-2026-10-06T01-53-54-734Z` 中的 20 章证据复测已知失败案例，调用真实模型、业务库只读。

真实复测可再追加 `--detect-only=19`（或 `6`）、`--state-only=16`（或 `4`）、`--api-only` 或 `--controls-only` 单独重跑相应阶段，避免重复消费已通过的案例。检测、状态或反例对照可加 `--model=模型名` 临时比较模型，不改业务配置。断言失败会非零退出，不能把调用完成或某次重试通过当成稳定准确率。

写作上下文统一用于起草、续写、选区修改、审稿与审后修订：先为输出和消息格式预留额度，NovelAI 先通过官方 token-count 接口核对完整材料，避免中文被 UTF-8 字节数误判超限；完整材料确实放不下时，再核对保守裁剪后的候选。其他服务或计数失败时仍以 UTF-8 字节数保守估算（不是精确 tokenizer 计数）。超限时依次裁剪较远正文、范文、当前正文的较远部分和非常驻设定，保护台本、Memory、常驻设定、作者要求和修改选区；审稿与补丁修订还会保护完整正文。必要材料本身放不下时停止调用，预览显示预算及裁剪详情。整章生成从台本首事件重新创作，不带入本章旧稿，也不以旧稿触发 Lorebook；续写才带入当前正文，审稿与选段修改保留各自需要的正文。作者批注和本次修改要求位于最终任务附近。Lorebook 统一检查批注、修改要求与附近正文；完整台本只在整章任务中参与激活，续写/选区修改不会仅因远期台本关键词激活条目。

默认文笔规则已简化为具体表达、避免重复、人物口吻与自然节奏等建议，不设置禁用词、句长或修辞数量配额；新版审稿按作者文风给文笔分，不再用旧禁词/标点扫描机械扣分。原封未改的旧默认模板自动升级，自定义文本保持不变。

本章作者批注位于台本下方，逐章独立保存。右侧 Memory 是全书唯一的当前有效记忆；切换章节不更换记忆，点击确认定稿会先根据已保存正文自动整理 Memory 建议，作者可编辑并核对；确认后在同一事务中更新当前 Memory、定稿并保存历史，取消或整理失败不改动当前记忆。历史版本只读，生成和审稿不叠加旧版逐章差分摘要或前 N 章摘要。近期正文仅用于衔接，不另建记忆。

写作台的「固定写作要求」预填通用创作与去 AI 味模板，可直接编辑、删减或补充，并可恢复默认。整章生成、续写与正文修订仅使用当前文本，删除的模板规则不会在后台补回。旧版通用规则与原有自定义要求一次性合并到此处。写法冲突时，本次要求和作者批注优先，其次作者明确自定义要求及写作指引，再次文风指南与范文参考，最后是模板中保留的默认文笔建议；范文不提供本书剧情事实。Memory 整理只记录事实，不使用创作文风模板。

## 环境变量

在根目录创建 `.env` 文件：

| 变量 | 说明 | 默认值 | 必需 |
|------|------|--------|------|
| `PORT` | 后端端口 | `3001` | 否 |
| `HOST` | 监听地址，本地运行可设 `127.0.0.1` | `0.0.0.0` | 否 |
| `NODE_ENV` | 运行环境 (`production` / `development`) | 无 | 否 |
| `JWT_SECRET` | JWT 签名密钥 | **必填，无默认值** | **是** |
| `DB_PATH` | SQLite 数据库路径 | `data/app.db` | 否 |
| `ALLOWED_ORIGINS` | 允许的 CORS 域名，多个用逗号分隔 | 生产环境无默认值 | 否 |

> `JWT_SECRET` **必须设置**，缺失时服务启动会报错退出。

## 部署

项目已配置 Railway 部署（`railway.json`），推送代码后在 Railway 关联仓库即可自动部署。

### Railway 部署注意事项

- **必须设置环境变量** `JWT_SECRET`
- 建议设置 `NODE_ENV=production`
- **必须挂载持久化 Volume** 到 `data/` 目录（SQLite 数据库），否则每次重启数据会丢失
- 可选：`ALLOWED_ORIGINS` 如不设置，生产环境默认拒绝所有跨域请求

### 首次部署后

1. 在 Railway Dashboard 打开项目 Shell，运行 `npm run db:seed` 初始化数据库
2. 默认账户：`admin` / `950711`

模型返回 `finish_reason=length` 时，正文生成保留已收到内容并归档为未完成草稿；编辑区提供继续写和手工补全确认，保存、重开和撤销均保留完成状态，未完成正文不能定稿。Memory 建议、选段替换及其他完整输出任务遇到截断会拒绝结果，不覆盖原稿或记忆，也不按相同输出上限自动重复调用。正常结束仅表示服务端未报告长度截断，仍需作者核对台本是否写全。

写作台篇幅目标按作品设置的每章字数至其 1.25 倍计算（4000 对应 4000–5000 字），含标点、不含空白。系统提示词与整章生成/续写的本次任务都明确目标；续写按已有正文与新增正文的合计计算。正文区实时展示目标和不足/超出提示，不自动追加剧情或阻止保存。上下文面板分别展示系统提示词和用户提示词。

选段修改会提示精简后变长、异常扩写和疑似重复前后文；提示仅为文本规则检查，不代替衔接核对。修改建议展示原选区/替换字数，以及高亮替换范围的拼接预览。异常建议需修正或明确核对后才可接受。可从 server 目录运行 `node_modules/.bin/tsx ../client/tests/revisionWarnings.ts` 检查这些规则。

Lorebook 条目编辑支持“AI 整理润色”：使用参数中当前选择的创作模型，仅发送该条目名称、分类和正文，按标题及条目整理语言。人物和世界观按资料选用分节，保留事实、计划、猜测、秘密、知情范围及待核对矛盾。结果先对比和编辑，再采纳到条目；点击完成编辑并保存项目设置后持久化。模型调用遵守现有上下文与输出预算，失败或截断不覆盖原文。

写作台生成现在分为写前核对、正文生成、写后核对：直接提交完整台本，由程序明确事件顺序与停笔位置，当前创作模型核对 Memory 时间点、事实/知情边界，并从文风指南整理带原文依据的简短要求。固定写作要求和作者批注原样保留；材料冲突会显示双方原句并停止正文调用，不自动选取历史 Memory 或改写设定。写前核对仅对当次输入和上下文版本有效。

正文完整生成后先自动保存原稿，再自动执行一次全文精修（三层诊断：故事→用笔→表达、定点改稿、采用前候选复核），展示对比供作者采用，不先执行另一轮重复审稿。截断草稿等续写完整并保存后再自动精修；保存失败时跳过精修；精修失败保留已保存正文，允许用「全文精修」重试。该按钮也用于作者修改正文、台本、批注或文风后手动再次精修。手工编辑、打开章节、采用修订和确认定稿均不自动触发精修，避免循环。每轮通常最多三次模型调用，没有可直接修复的问题则跳过后续调用。每项诊断须定位正文并引用现有材料，区分依据已有材料可直接修复和需作者决定的问题；需新增动机、关键证据、能力、经历或裁定冲突的，单独列出，不写入候选。补丁必须独立、唯一定位到可修问题；候选复核再次检查归属、推断强度、事实来源和前后衔接，未放行、核验缺失或失败的修改不进入可采用稿。预览展示前后字数、原文/替换文字、被拦下的修改与待作者决定事项；采用后自动保存，其余文字保持原样。不循环改稿或自动定稿。表达扫描仅作为可丢弃的定位线索，不按禁词、标点或心理直写扣分；精修方法独立于可编辑固定写作要求。语义复核仍依赖模型，不能保证发现全部错误。字数由程序统计，台本写完而篇幅偏短时提示展开已有情节，不在章尾自动加戏。写前/写后记录与补丁候选均归档，这些步骤不会更新 Memory；权威记忆仍由作者保存或确认定稿时更新。

这部分参考 [Oh Story](https://github.com/ccbrz/oh-story-claudecode) 的单章约定、文风裁决、事实与知情检查、定点修订设计（参考版本 `74080143dd1ac9a39a930fafd99a0dbbe61b946a`），适配现有 SQLite、Lorebook 与修订记录；未引入其运行时依赖或禁词/标点阻断规则。来源许可见 `THIRD_PARTY_NOTICES`。离线回归：`pnpm --filter server test:writer-workflow`；原有写作台回归仍运行 `pnpm --filter server test:writer`。

Memory 的记忆进度自动维护，只展示、不再要求作者填写章号。章节定稿保存完整 Memory、截至章节和前文来源校验；修改前、定稿前、恢复前均备份原记忆。回到已定稿章节重写时，可在 Memory 点击“重写本章 · 恢复章前记忆”，或由生成按钮引导到该预览，比较后明确恢复至前一章结束的有效版本，再重新生成；恢复同时保留当前项目设置和未保存记忆备份，不更改正文。历史抽屉也可预览恢复可用版本。只有一份当前权威记忆，历史不会被静默混入请求。旧章正文修改或重新定稿后，后续旧快照保留但标记失效；后续正文保留为待核对，需按新前文重新确认。来源不明、前文未定稿、来源正文已变更的快照不可恢复；缺少对应版本时明确提示，第一章可由作者明确选择空 Memory 起步，不臆造历史记忆。旧数据缺少来源校验信息仍可查看，但不追认其有效性。恢复检查权限、输入版本和前文变更，备份与恢复同一事务完成。回归：`pnpm --filter server test:writer-memory`。每次完整生成通常增加一次写前核对，以及最多三次精修调用；服务失败会明确提示；写前模型输出截断、结构无效或引用不成立时，明确提示后按原始资料生成，不采用未验证的摘要，Memory 时间标记保护仍执行。生成成功的正文仍保留。
